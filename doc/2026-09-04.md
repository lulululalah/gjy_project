# 2026-09-04 项目整理、模型测试与可视化记录

## 一、项目目标

当前项目处于 AI 模型预测阶段，后续才进入 CAD 面删除阶段。当前识别采用三分类：

- `0 = background`：普通背景面
- `1 = rivet`：铆钉
- `2 = surface_feature`：表面特征，包含原生贴花、原生窗户和后加贴花

当前验收重点不是单纯追求总体 F1，而是：

1. 铆钉允许少量漏检，但尽量不出现误检；
2. surface 允许一定漏检和误检；
3. 大面积机身、机翼或发动机壳体不能被离谱地预测为 surface；
4. 预测结果必须能够映射回正确的 STEP 面 ID，供后续删除流程使用。

## 二、当前代码架构

当前主流程为：

```text
STEP
  -> Detector 导出面特征和邻接图
  -> 独立 rivet specialist 编码器
  -> 独立 surface specialist 编码器
  -> rivet/surface 阈值判定和类别合并
  -> 光滑壳体保护规则
  -> 预测 CSV 和真值对比可视化
```

当前模型采用两个相互独立的 GNN specialist：

- rivet 分支专门学习铆钉特征；
- surface 分支专门学习贴花、窗户等表面特征；
- 最终输出时进行类别合并，避免两个类别共享同一个分类头而互相过度影响。

代码中保留了部分 AAGNet 风格的输入编码思路，但没有依赖外部 AAGNet 工程。`doc/AAGNet借鉴方案2026-09-04.md` 仅作为设计记录保留，不参与程序运行。

## 五、可视化处理

### 交互窗口问题

多次尝试直接打开 OCC 交互窗口时，终端能够输出：

```text
WNT window created.
Display3d class successfully initialized.
```

但 Windows 进程的 `MainWindowHandle` 为 0，桌面没有出现可见的 OCC 窗口。说明模型读取、OpenGL 初始化和渲染对象创建都正常，问题集中在当前桌面会话对 PythonOCC/WNT 窗口的显示接管，而不是模型或预测代码错误。

### PNG 离屏可视化

为避免每次依赖不稳定的桌面窗口，在 `python/visualize_rivets.py` 中新增：

```text
--screenshot <PNG 路径>
```

该参数使用与交互窗口完全相同的面着色逻辑，通过 OCC `View.Dump()` 输出 PNG，不会修改预测标签，也不会加入额外的后处理筛选。

本次生成的文件：

```text
work/viz_109_current.png
work/viz_dc10_current.png
work/viz_747_current.png
work/viz_gulfstream_current.png
```

颜色含义：

- 绿色：铆钉预测正确；
- 蓝色：surface 预测正确；
- 紫色：铆钉误检、漏检或类别错误；
- 红色：surface 误检；
- 黄色：surface 漏检；
- 灰色：背景和模型上下文。

## 八、下一步建议

1. 优先审计 747-400 的 10 个铆钉误检，目标是提高铆钉 Precision，同时不能破坏其他飞机的铆钉召回。
2. 审计 109 的 46 个背景到 surface 误判，记录面面积、曲面类型、邻接组件、光滑连通组和真实几何位置。
3. 对 747-400 和 Gulfstream 的背景 surface 误判做同样的跨飞机对比，判断是否存在共同的壳体拓扑模式。
4. 保持当前模型作为基线，不在可视化阶段人为删除预测面或使用真值过滤预测结果。
5. 后续如继续修正模型，应重新生成四架测试飞机的预测 CSV 和 PNG，并同时报告总体准确率、铆钉 Precision/Recall、surface Precision/Recall、背景误判数和最大误报面。
6. CAD 面删除功能尚未实现，当前输出只能作为删除候选，不能直接对原始 STEP 做不可逆修改。
