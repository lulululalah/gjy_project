# BRep 微小特征识别与去除 — 算法设计（讨论稿）

> 状态：讨论稿 v0.1
> 目标读者：项目内部讨论
> 写作日期：2026-06-12

本文在现有「纯图方案」(`STEP → FaceFeature → Face Graph → GNN → Face Label`) 的基础上，
向完整目标扩展，给出端到端的算法流程、模块设计、测试用例与实施计划，作为后续讨论的底稿。

---

## 1. 背景与目标

### 1.1 业务目标

对于 BRep 样条模型（飞机工业零件等），自动完成：

1. **识别**模型表面上的微小特征：铆钉、小孔、窗口、贴花（decal）、小倒角/小凸台等。
2. 对识别出的特征执行**去除 / 补全**（defeaturing）：删除微小几何并把周围曲面补平。
3. 输出干净的简化 BRep，用于后续网格离散化与仿真。

### 1.2 为什么要做

微小特征对仿真结果影响很小，但会在网格离散化时造成网格密集聚集，
显著增加单元数量与求解时间。去除这些特征可以在几乎不损失仿真精度的前提下加速整个流程。

### 1.3 与当前代码状态的差距

| 能力 | 现状 | 目标 |
|------|------|------|
| 面级特征提取 | ✅ 已有（14 维节点特征 + 边类型） | 扩展节点/边特征 |
| 图构建 | ✅ 已有（面=节点，边=BRep edge） | 增加 k-hop 局部窗口子图 |
| 标签来源 | ⚠️ **手工启发式规则**（面积/半径阈值） | **合成注入 + 自动真值标注** |
| GNN | ✅ 3 类面分类（NNConv） | 多任务：语义分割 + 实例分组 + 操作预测 |
| 特征实例 | ❌ 无（只有逐面标签） | 把面聚合为特征实例 |
| 几何去除/补全 | ❌ 无 | OCC defeaturing + 验证 |
| 评估指标 | ⚠️ 仅训练精度 | 实例级 AP、几何有效性、网格/仿真加速比 |

**核心改动建议**：当前标签由 `Workflow.cpp::ClassifyFaceForTraining()` 里的硬阈值规则生成，
这条路本质上是「用规则去监督一个本应学规则的模型」，存在循环依赖、且难以覆盖复杂模型。
建议改为 **「在干净模型上合成注入微小特征 → 注入时直接记录真值标签」**，
这样真值是构造出来的、100% 准确，GNN 的学习空间也不会被规则提前裁死。

## 3. 模块一：数据合成与自动标注

这是与现有架构差异最大、也是最关键的模块。

### 3.1 思路

不在已有脏模型上猜标签，而是：

1. 收集 / 准备一批**干净**的飞机工业零件 BRep（无微小特征，或微小特征已知）。
2. 用程序化的**特征注入器**在干净模型表面随机添加微小特征。
3. 注入的瞬间，我们**完全知道**哪些新面属于哪个特征、应执行什么操作 → 直接写出真值标签。

好处：

- 真值精确、无需人工标注。
- 可控地生成海量、分布均衡的样本（尺寸、位置、密度、特征类型可调）。
- 同时天然得到「去除前 / 去除后」的配对，可用于验证去除算法（注入的逆操作即是正确答案）。

### 3.2 特征分类法（taxonomy）

为每种微小特征定义：几何形态、典型的 BRep 面构成、对应的去除操作。

| 特征类型 | 几何形态 | 典型面构成 | 去除操作 |
|----------|----------|------------|----------|
| 铆钉 rivet | 凸起半球/圆柱台 | 1 顶面 + 1~N 侧面（凸边界） | 删除凸起，补平基面 |
| 小孔 hole | 通孔/盲孔 | 圆柱内壁 + (盲孔)底面，宿主面带内环 | 删除孔面，封闭宿主面内环 |
| 窗口 window | 带圆角的开口 | 内壁面 + 圆角面 + 宿主内环 | 同孔，封闭内环 |
| 贴花 decal | 印在曲面上的样条片 | 宿主面被分割出的小样条面（共面/近共面） | 合并回宿主面 |
| 小倒角 fillet | 小半径过渡面 | 圆柱/环面过渡条带 | 删除过渡面，延伸相邻面相交 |
| 小凸台 boss | 矩形/圆形凸起 | 顶面 + 侧面 | 同铆钉 |

> 讨论点：第一阶段建议先聚焦 **铆钉 + 小孔** 两类（与现有 label=2 hole 相关工作衔接最紧），
> 跑通端到端后再逐步加入窗口/贴花/倒角。

### 3.3 注入器设计

每个注入器是一个 C++ 函数（基于 OCC），输入干净 shape + 随机参数，输出修改后 shape + 注入记录。

- **铆钉/凸台**：在宿主面上选采样点，沿法向 `BRepPrimAPI_MakeCylinder/MakeSphere` 造凸体，
  `BRepAlgoAPI_Fuse` 融合。记录融合后新增的 face id。
- **孔/窗口**：造圆柱/带圆角棱柱工具体，`BRepAlgoAPI_Cut` 挖孔。记录被切出的内壁面、宿主面内环。
- **贴花**：在宿主面上 imprint 一条样条边界（`BRepFeat` / split face），把分割出来的小面标为 decal。
- **倒角**：`BRepFilletAPI_MakeFillet` 在选定边上加小半径圆角，记录生成的过渡面。

注入参数（用于生成多样性 & 课程学习）：

- 尺寸范围（绝对 mm + 相对于宿主面/模型包围盒的比例）
- 每个模型注入的数量、空间分布（随机 / 阵列，铆钉常成排）
- 宿主面类型（平面 / 圆柱 / 样条）
- 是否相互重叠/邻接（增加难例）

### 3.4 真值标注格式

每个生成模型导出 `<model>.step` + `<model>.labels.json`：

```json
{
  "model_id": "wing_rib_007_aug03",
  "base_model": "wing_rib_007",
  "faces": [
    {"face_id": 142, "semantic": "rivet", "instance_id": 5, "operation": "remove_protrusion"},
    {"face_id": 143, "semantic": "rivet", "instance_id": 5, "operation": "remove_protrusion"},
    {"face_id": 0,   "semantic": "background", "instance_id": -1, "operation": "keep"}
  ],
  "instances": [
    {"instance_id": 5, "type": "rivet", "host_face": 12,
     "inverse_op": {"kind": "remove_protrusion", "tool": "cyl", "params": {...}}}
  ]
}
```

三层标签，对应 GNN 的三个任务：

- `semantic`：面的特征类别（background / rivet / hole / window / decal / fillet …）
- `instance_id`：同一物理特征的面共享一个实例 id（用于实例分割）
- `operation`：该面/实例对应的去除操作类型（keep / remove_protrusion / fill_hole / merge_decal …）

> 关键：`face_id` 必须在注入后稳定可复现。建议在导出 STEP 时写入持久面标识
> （OCC `TDataStd` / 自维护的确定性遍历顺序），保证标注 json 与后续重新加载 STEP 时面顺序一致。
> 这是整个数据链路的隐藏风险点，需优先验证（见测试 T1）。

### 3.5 基模型来源

- 现有 `data/dirty_training_set/` 的 30 个 STEP（先做清洗/筛选，挑出相对干净的作基底）。
- 公开 CAD 数据集（ABC / Fusion360 Gallery / MFCAD 等）中的机械零件作补充。
- 同一基模型多次随机注入 → 数据增强。

## 4. 模块二：图构建与局部窗口

在现有图构建上扩展，并引入 window 机制。

### 4.1 节点特征（在现有 14 维上扩展）

现有：`relativeArea, compactness, surfaceType, nx, ny, nz, centerZ, meanCurvature, radius, numWires, innerWireCount, minInnerWireLength, maxInnerWireLength, numEdges`

建议补充（讨论）：

- 包围盒尺寸（长/宽/厚的近似），尤其「最小尺寸」对微小特征极敏感。
- 高斯曲率 / 主曲率两个分量（现仅 meanCurvature）。
- 面积相对于**邻域**面积的比值（局部对比，比全局 relativeArea 更能凸显「小」）。
- 法向相对于宿主/邻面的偏转统计。
- 是否为内环宿主、内环数量已在，但可加内环面积占比。

> 注意：`centerZ`、绝对坐标这类**非平移/旋转不变**的特征对泛化不利，建议弱化或改为局部相对量。

### 4.2 边特征（在现有 3 类边上扩展）

现有：`edge_type ∈ {convex=1, concave=-1, smooth=0}`

建议补充：

- 二面角（连续值，比离散 convex/concave 信息量大）。
- 共享边长度（绝对 + 相对）。
- 边的曲线类型（直线 / 圆 / 样条）与曲率。
- 两面面积比（小面接大面是微小特征的强信号）。

### 4.3 局部窗口（window）机制 — 核心

微小特征本质是**局部**的：判断一个面是不是铆钉侧壁，只需看它周围 1~3 圈邻居。
这正是用户提到的「通过局部 window 就能识别」。两种等价实现，建议组合：

**(a) k-hop 子图采样（训练时）**

- 以每个面为种子，取其 BRep 邻接图上的 k-hop（k=2~3）邻域子图。
- 子图中心面做分类，子图提供局部上下文。
- 优点：样本量大（每个面一个样本）、天然平移不变、可均衡正负样本、对大模型可扩展。

**(b) 受限感受野（推理时）**

- GNN 层数 L 决定感受野半径 = L-hop。取 L=2~3 即可让每个面只聚合局部信息。
- 推理可直接整图前向，但因层数浅，每个面的决策只依赖局部 → 等价于滑窗。

**为什么有效**：

- 局部性 → 同一种铆钉无论出现在机翼还是机身，子图长得几乎一样 → 强泛化。
- 可扩展 → 不受整模型面数影响，超大模型也能逐窗处理。
- 类别均衡 → 背景面太多时，可对背景子图下采样。

> 讨论点：窗口半径 k 的选择需做消融。铆钉只需 k=1~2；窗口/带圆角孔可能需要 k=3。
> 可对不同特征类型用不同 k，或统一取较大 k 让模型自己学。

## 5. 模块三：GNN 模型设计

### 5.1 多任务输出

在现有 `RivetGNN`（3 层 NNConv）骨干上，改为共享编码器 + 三个任务头：

```
        ┌─────────────────────────────────────────┐
Graph ─►│  共享 GNN 编码器 (NNConv ×L, 含边特征)    │─► 每个节点 embedding h_i
        └─────────────────────────────────────────┘
                 │            │              │
                 ▼            ▼              ▼
          [语义头]      [实例边界头]     [操作头]
          逐面类别      逐边 same/diff   逐面操作类型
          (softmax)     (edge MLP)       (softmax)
```

- **语义头**：节点分类，类别 = {background, rivet, hole, window, decal, fillet, …}。
- **实例边界头**：对每条图边预测「两端面是否属于同一特征实例」(affinity)。
  推理时对「特征面」子图按 affinity 做连通分量 → 得到实例。
  这种「逐边亲和度 + 连通分量」比直接学实例 id 更稳，且天然利用了图结构。
- **操作头**：预测该面/实例对应的去除操作类型（与 labels.json 的 `operation` 对齐）。
  也可做成实例级（对实例 embedding 池化后分类）。

### 5.2 损失与类别不平衡

- 语义/操作：加权交叉熵（沿用现有 `compute_class_weights` 思路，背景面远多于特征面）。
- 实例边界：二分类，正样本（同实例）通常远少 → focal loss 或正样本上采样。
- 子图采样时对背景种子下采样，缓解不平衡。

### 5.3 与现有代码的衔接

- `train_rivet_gcn.py` 的 `RivetGNN` 拆成 `Encoder` + 三个 head，loss 改为多任务加权和。
- `build_graph()` 增加：边特征扩展、k-hop 子图采样选项、三套标签列。
- 真值来源从 CSV 的 `semanticTag` 改为合成标注 json（C++ 导出时一并写出）。

> 讨论点：是否一步到位上多任务，还是先把「语义分割」单任务用合成真值跑通、确认数据链路正确，
> 再逐步加实例头与操作头。建议**分阶段**（见第 8 节里程碑）。

## 6. 模块四：几何去除与补全（Defeaturing）

识别只是前半程，真正产生价值的是把特征删掉并补平。这块当前代码完全没有，需新建。

### 6.1 OCC 工具

- OCCT 7.4+ 提供 `BRepAlgoAPI_Defeaturing`（`RemoveFeatures`）：
  传入要删除的 face 集合，自动删除并尝试用相邻面延伸/相交补洞。**优先用它打底**。
- 备选 / 兜底：
  - 凸起（铆钉/凸台）：`BRepAlgoAPI_Cut` 用工具体减去，或直接删面后 `ShapeUpgrade` / 缝补。
  - 孔/窗口：删除内壁面 + 用 `ShapeFix_Wire` 填平宿主面内环（去掉内环 → 重建面）。
  - 贴花：把分割出的小面与宿主面 `ShapeUpgrade_UnifySameDomain` 合并（同域统一）。
  - 倒角：删除过渡面 + 延伸相邻两面求交补尖角。

### 6.2 执行流程

```
实例列表 (按 GNN 结果) ──► 按操作类型分组
   ├─ remove_protrusion: 收集凸起面 → Defeaturing / Cut
   ├─ fill_hole:         收集孔壁面 → Defeaturing / 内环封闭
   ├─ merge_decal:       UnifySameDomain
   └─ remove_fillet:     删面 + 延伸求交
        │
        ▼
   逐实例执行（建议单实例独立 try，失败回滚不影响其他）
        │
        ▼
   有效性校验
```

### 6.3 有效性校验（关键）

每步去除后必须验证，避免产出坏 BRep：

- `BRepCheck_Analyzer`：拓扑/几何有效性。
- 是否仍为闭合实体（watertight solid）。
- 体积变化在阈值内（微小特征 → 体积变化应很小；变化过大说明删错了）。
- 包围盒 / 关键尺寸基本不变。
- 失败的实例：回滚该实例的修改，记录日志，宁可不删也不产坏几何。

### 6.4 用合成数据自验证

合成阶段我们保存了「注入前的干净模型」。因此：

> 去除算法的正确性 = 「对注入后模型执行去除」是否能恢复到「接近注入前模型」。
> 可用 Hausdorff 距离 / 体积差直接量化，不需人工判断。

## 7. 测试用例设计

分四层：单元 → 几何 → 模型 → 端到端，每层都有可量化指标。

### 7.1 数据链路单元测试

- **T1 面标识稳定性**（最高优先级）：注入导出 STEP 后重新加载，face_id 与 labels.json 完全对齐。
  这是整个监督信号的前提，必须先验证。
- **T2 注入器正确性**：每种注入器生成后，`BRepCheck_Analyzer` 通过；新增面数量符合预期。
- **T3 图构建一致性**：同一模型多次构图，节点/边、特征数值确定可复现。
- **T4 特征归一化**：训练/推理使用同一份 `stats`，无泄漏、无错位。

### 7.2 GNN 识别评估

在**留出的合成测试集**（基模型与训练不重叠）上：

- 语义分割：逐面 Precision / Recall / F1（按类别）、mIoU。
- 实例分割：实例级检测 AP（按 IoU 阈值匹配预测实例与真值实例），漏检/误检率。
- 操作分类：准确率、混淆矩阵。
- 鲁棒性：对特征尺寸（接近阈值的临界尺寸）、特征密度（密集铆钉阵列）、宿主面类型（平面 vs 样条）分桶报告。
- 消融：窗口半径 k、边特征有无、节点特征子集、是否多任务。

### 7.3 几何去除评估

- 去除后 `BRepCheck` 通过率。
- **恢复误差**：去除结果 vs 注入前干净模型的 Hausdorff 距离 / 体积差分布。
- 误删率（删了不该删的）、漏删率（该删没删）。
- 单实例失败回滚是否生效（不污染整体）。

### 7.4 端到端 / 业务价值评估（最终目标）

这是项目真正要证明的：**去特征后网格更少、仿真更快、精度损失可接受**。

- **网格指标**：相同网格参数下，去特征前后的单元数 / 节点数对比（应显著下降）。
- **仿真加速比**：相同算例，去特征前后求解时间对比。
- **精度损失**：关键物理量（应力峰值、模态频率等）去特征前后偏差，需在可接受阈值内。
- 选 3~5 个代表性真实零件做案例研究。

### 7.5 回归与持续验证

- 每次改模型/改特征，跑固定合成测试集，指标进表格（防退化）。
- 沿用现有可视化（`visualize_rivets.py` 着色）做人工抽检，扩展到多类别多颜色 + 实例分组着色。

## 8. 里程碑与实施计划

建议小步快跑，每步都有可验证产出，避免一次性铺开。

| 阶段 | 目标 | 关键产出 | 验证 |
|------|------|----------|------|
| M0 | 面标识稳定性打底 | 确定性面 id + 注入/重载对齐 | T1 通过 |
| M1 | 铆钉+小孔注入器 + 真值导出 | 注入器、labels.json、配套 STEP | T1~T3 |

## 9. 待讨论的开放问题

1. **标签来源**：是否认可「合成注入 + 自动真值」替代现有启发式规则标签？（本设计的核心假设）
2. **面标识**：用 OCC 持久标识还是自维护确定性遍历顺序？需先做可行性验证。
3. **第一阶段范围**：先只做铆钉+小孔，还是同时铺更多类型？（建议前者）
4. **实例化策略**：逐边亲和度 + 连通分量，vs 直接预测实例 id / 聚类？
5. **去除工具**：`BRepAlgoAPI_Defeaturing` 在你们的 OCC 版本是否可用、对样条面效果如何？需先做 spike。
6. **基模型数据**：现有 30 个脏模型够不够做基底？是否引入公开数据集？
7. **窗口 vs 整图**：训练用子图、推理用整图浅层网络，这套组合是否接受？
8. **样条面的特殊性**：飞机零件多为样条曲面，曲率/法向特征在样条上是否稳定、需不需要额外采样点特征？
9. **评估闭环**：网格/仿真加速验证需要哪条仿真工具链？谁来提供算例与可接受精度阈值？

## 10. 小结

- 最大的结构性建议：**把训练监督信号从「手工规则」换成「合成注入的真值」**，这决定了模型上限。
- 识别侧：在现有面图 + NNConv 上扩展为**多任务（语义/实例/操作）+ 局部窗口**。
- 去除侧：新建 **OCC defeaturing 模块**，并用「合成数据的注入逆操作」做自动正确性验证。
- 测试侧：建立**合成测试集的量化指标**，并最终以**网格/仿真加速比**证明业务价值。
- 落地节奏：从「铆钉+小孔的语义分割」跑通端到端，再逐步加实例、操作、更多特征类型与几何去除。
