## 三、今天保留的归一化代码修改

### 1. C++ 几何特征导出

修改文件：

- `include/FeatureInfo.h`
- `src/FeatureExtractor.cpp`
- `src/Workflow.cpp`
- `src/main.cpp`

主要逻辑：

1. 使用 OCCT 对整模型计算真实包围盒。
2. 取最长包围盒边长 `L`，统一缩放系数为 `scale = 2 / L`。
3. 坐标使用同一个 scale，不分别拉伸 X/Y/Z，保持飞机和汽车的长宽高比例。
4. 导出包围盒中心和 `normalizationScale`，不改变 STEP、B-Rep、拓扑或 face_id。
5. 批量训练导出命令增加可选输出路径，默认旧用法不变，可以安全生成新 CSV 而不覆盖旧数据。

面积修正：

- `BRepGProp::SurfaceProperties(face)` 计算的是带修剪边界的 `TopoDS_Face` 面积。
- 发现部分反向面会返回负符号，因此现在对裁剪面面积和邻面面积使用绝对值。
- `relativeArea` 仍保留，并使用全部绝对裁剪面面积作为分母。

### 2. Python 归一化特征

修改文件：

- `python/train_rivet_gcn.py`

新版特征遵循：

```text
normalizedPosition  = (position - bboxCenter) × scale
normalizedArea      = abs(trimmedArea) × scale²
normalizedLength    = length × scale
normalizedRadius    = radius × scale
normalizedCurvature = curvature / scale
```

新增或替换的尺度相关特征：

- `normalizedTrimmedArea`
- `normalizedPerimeter`
- `normalizedMeanCurvature`
- `normalizedRadius`
- 归一化内轮廓最小/最大长度
- 归一化邻面平均/最大面积
- 归一化共享边长度
- 基于真实包围盒的轴向位置和径向距离

继续保留的无量纲特征：

- `relativeArea`
- `compactness`
- 面积比
- 法向点积
- 二面角
- 边/邻面计数和比例
- 曲面类型 one-hot

新 checkpoint 的统计文件写入 `feature_schema_version=2`。旧 checkpoint 仍能沿用旧的 `feature_cols` 读取新版 CSV，已用 Y-20 的 357 个面验证旧基线兼容推理。

## 六、明天的执行顺序

### 第 1 步：建立真正独立的 train/val/test 口径

今天的 normalized v2 训练为了复现旧基线口径，使用 test5 选择 checkpoint，因此只能作为特征消融，不能作为最终泛化结果。

明天从 normalized train14 中固定划出 3 个验证模型：

- `95- 737-800-4 CREO STP_boeing_737_cj_wing_rivets.step`
- `68- KC46 pegasus STP STL_Boeing KC-46 Peguses v4_wing_rivets.step`
- `221-cessna-model-grand-caravan STP_cessn CARAVAN v13_wing_rivets_decals.step`

形成：

- train11：只用于反向传播；
- val3：只用于 checkpoint 选择；
- test5：保持完全不动，只在最终候选确定后评估一次。

所有切分继续按完整 `model_name/graph_id`，禁止面级随机切分。

### 第 2 步：先做 normalized v2 的训练模型误差审查

用今天的 normalized v2 checkpoint 对 train14 全部面运行：

```powershell
& 'D:\Anaconda\envs\cad_graph_env\python.exe' `
  'python\audit_rivet_gcn_predictions.py' `
  --csv 'data\plane_model\plane_model_face_train_14_normalized_v2.csv' `
  --model 'work\rivet_gnn_split14_5_window_normalized_v2_epoch60.pth' `

  --out 'work\normalized_v2_train14_audit.csv' `
  --summary-out 'work\normalized_v2_train14_audit_summary.csv' `
  --window-hop 2
```

重点比较：

1. 91-737 的 26 个 decal 是否仍全部变成 window；
2. 6--78 的 background → decal 是否减少；
3. 95-737 中 decal 与 window 的面积/轮廓关系；
4. 错分 decal 是变成 background 还是 window；
5. 高置信度错误是否可能是漏标，而不是直接当 hard negative 使用。

用户应优先人工确认 91-737 的 face_id 和 JSON 标签。确认前不自动改标签。

### 第 3 步：分离“训练过程”和“选 checkpoint”问题

今天第 1 轮 mIoU 最高，但 decal F1 很低；继续训练后 mIoU 又持续下降。明天应做一个小而独立的训练器修改：

1. 每 5 epoch 才做一次完整 val3 验证，降低耗时；
2. 同一次训练同时记录：mIoU、foreground macro F1、decal F1 和 background FP；
3. 分别保存 `best_miou` 与 `best_foreground_f1`，不使用门控或模型组合；
4. 任何前景类别完全未命中时，不允许作为 foreground 最佳 checkpoint；
5. 最多先跑 60 epoch，不直接运行 150 epoch。

这个修改只影响验证与保存，不改变推理输出；最终仍是单模型四分类 `argmax`。

### 第 4 步：只有标签审查完成后，才决定下一项特征或数据改动

面积不能单独区分 decal/window：

- 在 91-737 中，decal 中位面积约为 window 的 `0.131`；
- 在 95-737 中，decal 中位面积约为 window 的 `38.58`。

两个模型规律相反，因此不能增加面积阈值。若标签确认无误，应优先检查以下结构特征是否需要增强：

- decal 与宿主面的共面/光滑连续程度；
- 最大邻面与中心面的面积、法向和曲面一致性；
- 裁剪边界形状和边数分布；
- window 的重复排列/局部行列关系；
- 同一模型中 decal/window 的实例级组合信息。

不要在没有审查证据时直接提高 decal 权重或重复过采样同一批 decal。

### 第 5 步：最终 test5 验收门槛

新模型只有同时满足以下条件才考虑替换旧基线：

1. test5 mIoU 高于 `0.5025`；
2. background 误报低于 `914`，目标不高于本次的 `560`；
3. rivet 保持 `136/136`；
4. window 保持 `578/578`，且 window F1 不低于旧基线 `0.9031`；
5. decal 至少恢复到旧基线 `10/35`，A220 至少 `10/30`；
6. 不使用测试模型训练、挖 hard negative 或选择 checkpoint。

如果只降低背景误报、却继续牺牲 decal/window，则不替换旧基线。

## 七、明天禁止重复的方法

1. 不再把全部背景面一次加入训练；该方法会造成 decal/window 退化。
2. 不再使用今天已回滚的动态 background-ratio=5 方案。
3. 不直接用固定 hard-negative 清单全量替换随机背景，也不重复已失败的 10% hard-negative 配额。
4. 不使用 A220、109、A-10、80-777 或模型 1 的误报面训练。
5. 不加 specialist gate、阈值、人工规则或真值过滤到可视化。
6. 不以总体 accuracy 判断模型；必须查看四类 F1、IoU、召回和 background FP。
7. 60 epoch 已显示持续退化时，不继续跑 150 epoch。
