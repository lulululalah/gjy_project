# 当前架构说明

## 1. 目标

项目的终极目标不是只识别微小孔，而是建立一套统一的脏几何处理架构。

这套架构的目标应该是：

1. 从 STEP 中提取稳定的几何与拓扑信息
2. 构造统一的脏几何候选层
3. 对不同类型的脏几何候选进行识别
4. 将识别结果送入后续修复、删除、合并或其他处理流程

微小孔只是其中一种脏几何类型，不是整个系统的唯一目标。

## 2. 终极架构

终极目标架构可以概括为：

`STEP -> FaceFeature -> CandidateLayer -> Candidate Classifier / Processor`

其中：

- `FaceFeature` 是底层几何拓扑描述层
- `CandidateLayer` 是统一脏几何候选层
- `Candidate Classifier / Processor` 是候选识别与处理层

`CandidateLayer` 未来应该能够包含多种候选类型，例如：

- `HoleCandidate`
- `BossCandidate`
- `FilletCandidate`
- `SlotCandidate`
- `ThinSheetCandidate`
- 其他自定义脏几何候选

## 3. 当前阶段

当前代码还没有完整达到“统一候选层”的终极状态，但已经搭出了这个架构的前两层。

当前已经具备：

1. `FaceFeature` 层
2. `HoleCandidate` 作为第一种候选结构类型

也就是说，当前项目所处阶段可以描述为：

`STEP -> FaceFeature -> HoleCandidate -> HoleCandidate Classifier`

这是在验证：

- 候选结构层这条路线是否可行
- 对微小孔这类脏几何，候选结构表示是否优于单纯的面级分类

目前的实验结果说明：对微小孔，`HoleCandidate` 路线比单纯 `FaceFeature` 直接分类更接近目标。

## 5. 当前架构的真实状态

当前不是“两套并列业务逻辑”，更准确的说法是：

- `FaceFeature` 是统一底层描述层
- `HoleCandidate` 是当前已验证的第一种候选结构
- 未来还需要把更多脏几何类型也提升到候选层

所以当前状态可以总结为：

- 已经有底层统一表示
- 已经有一种候选结构实例
- 还没有完成统一 `CandidateLayer` 抽象

## 6. 当前还缺什么

距离终极架构，当前主要还缺下面几项：

### 6.1 缺统一 Candidate 抽象

现在只有 `HoleCandidateFeature`。

未来需要有统一候选抽象，例如：

- 统一字段子集
- 候选类型标识
- 候选公共接口

例如可以考虑未来引入：

- `candidate_type`
- `candidate_id`
- `host_region`
- `size_metric`
- `topology_context`

让不同候选类型能进入同一个候选层。

### 6.2 缺更多候选类型

现在只验证了 `HoleCandidate`。

后续还需要尝试增加：

- 小凸台候选
- 小圆角 / 小倒角候选
- 狭缝 / 薄片候选
- 其他典型脏几何候选

### 6.3 缺统一分类/处理接口

当前孔候选使用了单独训练脚本和可视化脚本。

未来应该逐步演进为：

- 候选统一导出格式
- 候选统一推理接口
- 候选统一处理接口

## 7. 当前阶段的正确理解

当前最重要的不是把所有脏几何一次做完，而是：

1. 保留统一底层 `FaceFeature`
2. 验证“候选结构层”这条路线是否成立
3. 用 `HoleCandidate` 作为第一种候选类型打样
4. 再向其他脏几何类型推广

因此，当前工作不是偏离原架构，而是在搭原架构中最关键的新层：

`CandidateLayer`

## 8. 后续建议

当前建议的后续推进顺序：

1. 保留 `FaceFeature` 作为统一底层原料层
2. 将 `HoleCandidate` 视为第一种候选类型，而不是独立系统
3. 在保持当前微小孔路线可用的前提下，开始设计第二类候选
4. 逐步抽象出统一的 `CandidateLayer`
5. 再把训练、推理、处理接口逐步统一

## 9. 当前结论

当前项目已经从“面级直接分类脏几何”迈出了关键一步：

- 底层仍然是面级几何/拓扑特征
- 但识别层开始向“候选结构层”演进

这与终极目标是一致的。

当前不是完整终态，但已经处于终极架构的正确方向上：

`STEP -> FaceFeature -> HoleCandidate(第一种 Candidate) -> Classifier`

后续的关键任务不是推翻已有代码，而是把 `HoleCandidate` 的经验继续推广成统一的 `CandidateLayer`。
