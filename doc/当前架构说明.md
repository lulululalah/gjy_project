# 当前架构说明

## 1. 当前方向

项目当前采用纯图方法，不再使用 candidate 中间层。

当前主链路是：

`STEP -> FaceFeature -> Face Graph -> GNN -> Face Label / Visualization`

这里的核心判断是：
- 几何与拓扑信息仍然从 face-level 特征开始
- 结构关系通过图的邻接边表达
- 最终识别交给 GNN，而不是先做人手规则 candidate 筛选

## 3. 数据流

训练阶段：

1. `Detector.exe --train`
2. 生成 `data/full_training_set.csv`
3. `python .\python\train_rivet_gcn.py`
4. 输出 `rivet_gnn.pth` 与 `rivet_gnn_stats.npz`

推理阶段：

1. `Detector.exe --predict <file>`
2. 生成 `data/current_inference.csv`
3. `python .\python\visualize_rivets.py <file>`
4. 输出面标签并完成可视化

## 4. 为什么不再保留 candidate 路线

candidate 路线的主要问题是：
- 候选生成依赖手工规则
- 规则质量直接限制上层模型表现
- 对 GNN 来说，这会把学习空间提前裁死

当前决定改为纯图方法，意味着：
- 不再用传统候选筛选去约束问题空间
- 让 GNN 直接利用面特征和图结构学习判别逻辑
- 后续优化重点放在图表示、标签质量和模型结构上

## 5. 当前仓库状态

当前主流程已经移除 candidate 导出入口，也不再保留 candidate 训练/推理/可视化脚本。

仍然值得继续推进的方向是：
- 改进 `FaceFeature` 的表达能力
- 调整图构建与边特征设计
- 优化 GNN 结构、损失函数和类别不平衡处理
- 建立更稳定的训练集与评估集
